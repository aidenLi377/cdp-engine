## 一、系统总览

### 1.1 这是什么系统

CDP 自动圈人系统是一个**面向电商运营的人群数据引擎人群圈包**。它把原本需要在达摩盘（DMP）/ DataBank 后台手工点击、复制 JSON、人肉比对的繁琐流程，整合成一个 **"CSV 配置驱动 + 画布式圈人 + Chrome 插件一键执行"** 的自动化平台。

**核心价值**：
- **业务同学**：在画布上拖拽组合人群包 → 点"自动化圈人" → 浏览器自己跳去 DataBank 完成导入、提交、应用，全程不用手动点
- **配置管理员**：通过修改 CSV 维表 → 一键发布 → 所有用户实时同步新配置
- **管理者**：邀请制账号 + 操作审计 + 数据隔离 + 方案可公共化迁移

### 1.2 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     用户浏览器                                │
│  ┌──────────────────┐         ┌─────────────────────────┐  │
│  │  Vue3 前端 SPA    │ ◄─────► │  Chrome MV3 插件         │  │
│  │  (cdp-web)       │  消息桥  │  (DMP_PluginV2.1-CDP-   │  │
│  └────────┬─────────┘         │   Merged)               │  │
│           │ HTTPS             └────────────┬────────────┘  │
└───────────┼────────────────────────────────┼───────────────┘
            │                                │
            ▼                                ▼
┌─────────────────────────┐      ┌──────────────────────────┐
│   Flask 后端 (Gunicorn) │      │  达摩盘 DMP / DataBank    │
│   cdp_backend/app.py    │      │  databank.tmall.com      │
│   + SQLite 持久化        │      │  阿里系营销平台            │
│   + CSV 配置引擎         │      │                          │
└─────────────────────────┘      └──────────────────────────┘
```

**关键组件**：
| 组件 | 路径 | 说明 |
|------|------|------|
| 前端 | `cdp-web/` | Vue 3 + Element Plus + Pinia |
| 后端 | `cdp_backend/` | Flask + Gunicorn + SQLite |
| 配置 CSV | `*.csv`（根目录 13 张逻辑表 + 9 张维表 + 1 张参数表） | 配置引擎的数据源 |
| Chrome 插件 | `DMP_PluginV2.1-CDP-Merged/` | MV3，负责 DMP/DataBank 自动化 |
| 部署 | `deploy/` + `gunicorn.conf.py` | systemd 服务化部署 |

## 二、快速上手：10 分钟跑通一次完整圈人

> 给新同学的"傻瓜路径"，照做就能完成一次完整的圈人动作。

1. **登录** → 打开 https://duruo377.top → 输入账号密码（首次使用找管理员要邀请链接）
2. **装插件** → 数据引擎人群圈包右上角「下载插件」→ Chrome 打开 `chrome://extensions/` → 开"开发者模式"→ 拖入解压目录
3. **登录 DataBank** → 新标签页打开 https://databank.tmall.com → 用阿里妈妈账号登录（保持登录状态）
4. **回到数据引擎人群圈包** → 左侧组件库挑人群包（比如"类目公域行为"）→ 拖到画布 → 填参数（行为、类目、时间）
5. **组合** → 再拖一个"AIPL 状态"节点 → 两个节点之间选「交集」
6. **生成** → 点右上角「生成 JSON 参数」→ 右侧 JSON 区出现完整参数
7. **自动化** → 点「自动化圈人」→ 浏览器自动切到 DataBank → 看着它自己粘贴、确认、应用
8. **查看结果** → DataBank 显示"已应用" → 任务完成 ✅

全程**无需手动复制粘贴**，无需在 DataBank 里找菜单。

## 三、数据引擎人群圈包（NormalMode）详解

数据引擎人群圈包是用户日常待得最久的地方，本质上是一个**"可视化 DMP JSON 编辑器"**。

### 3.1 界面布局

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航：数据引擎人群圈包 | 数据引擎取数模板 | 达摩盘取数 | 管理后台 | 用户      │
├──────────────────────────────────────────────────────────────┤
│ ┌──────────┐ ┌────────────────────────────┐ ┌─────────────┐ │
│ │ 左侧面板  │ │        中央画布             │ │ 右侧 JSON 区 │ │
│ │ ┌──────┐ │ │  ┌──────┐    ┌──────┐     │ │ ┌─────────┐ │ │
│ │ │组件库│ │ │  │节点 A│ ∩  │节点 B│     │ │ │摘要/JSON│ │ │
│ │ │已发布│ │ │  └──────┘    └──────┘     │ │ │  Tab    │ │ │
│ │ │方案  │ │ │                            │ │ └─────────┘ │ │
│ │ └──────┘ │ │  ┌──────┐                  │ │ [复制参数]  │ │
│ │          │ │  │节点 C│                  │ │ [自动化圈人]│ │
│ │          │ │  └──────┘                  │ │ [跳转DB]   │ │
│ └──────────┘ └────────────────────────────┘ └─────────────┘ │
│ 底部工具栏：[存草稿] [清空] [撤销↶] [重做↷]      │
└──────────────────────────────────────────────────────────────┘
```

**左侧面板**通过 Tab 切换两种模式：
- **组件库**：13 类人群包组件（每个对应一张逻辑表）
- **已发布方案**：从数据引擎取数模板拉取的可复用方案，直接拖到画布

### 3.2 添加人群包（组件库）

**操作**：
1. 左侧切到「组件库」
2. 找到目标人群包（13 种之一，见附录 B）
3. **拖拽**到中央画布，或点击卡片上的「+」
4. 弹出该人群包的参数表单（字段由 `1.参数表.csv` 决定）

**典型字段类型**（对应参数表的 `Widget_Type`）：
| Widget 类型 | UI 形态 | 举例 |
|------------|---------|------|
| 复选组 | 多选 checkbox | 行为（浏览/收藏/加购/购买） |
| 搜索多选 | 带搜索的多选下拉 | 类目、品牌 |
| 单选组 | radio | AIPL 状态（A/I/P/L） |
| 列表输入 | 多行输入框 | 商品 ID 列表 |
| 数值_切换 | 数值+范围 | 消费频次、消费金额 |

### 3.3 节点操作：交/并/差

每两个相邻节点之间可以设置集合运算符：

| 运算符 | 代码 | 含义 | 典型场景 |
|--------|------|------|----------|
| **交集** | `n` | 同时满足两个条件 | "买过类目 A **且** AIPL 是 P" |
| **并集** | `u` | 满足任一条件 | "买过类目 A **或** 类目 B" |
| **差集** | `d` | 满足 A 但不满足 B | "浏览过 **但** 没购买" |

**注意**：第一个节点没有运算符（`null`），从第二个节点起才有。

### 3.4 撤销 / 重做 / 清空 / 存草稿

底部工具栏四个按钮：
- **存草稿**：把当前画布存为"草稿方案"到数据引擎取数模板，仅自己可见
- **清空**：清空画布（不影响已存草稿）
- **撤销 ↶ / 重做 ↷**：对画布上"添加节点、删除节点、改参数、改运算符"全部生效

### 3.5 生成 JSON 参数

**触发**：右上角「生成 JSON 参数」按钮

**背后做了什么**：
1. 前端把画布节点、运算符、参数打包发给后端 `/api/generate_json`
2. 后端 ConfigEngine 根据 `1.参数表.csv` + 各逻辑表，把"用户友好参数"翻译成 **DataBank 真正认识的目标 JSON**
3. 返回给前端，右侧 JSON Tab 显示完整参数

**为什么需要后端翻译**：DataBank 的 JSON 里有大量内部 ID（cateId、brandId、channelBizId 等），用户只需要选"女装-连衣裙"这种友好名称，由后端查维表替换为 ID。

### 3.6 跳转 DataBank 手动粘贴

**按钮**：「跳转 DataBank」

**作用**：直接 `window.open('https://databank.tmall.com/#/userDefinedAnalyses')`，让你手动粘贴 JSON 走老路。

> 💡 自动化圈人失败时的兜底方案。

### 3.7 一键自动化圈人（DataBank 插件）

**按钮**：「自动化圈人」（绿色高亮按钮，需要插件已安装）

**前置条件**：
- 插件已安装并启用
- 已在 DataBank 登录阿里妈妈账号
- 画布已生成 JSON 参数

**点了之后**：
1. 前端通过 `window.postMessage` 发送 `CDP_AUTOMATE_DATABANK` 消息
2. 插件 content script 收到 → 转发给 background service worker
3. background 打开/激活 DataBank 标签页
4. 注入 `databank-automation.js`，开始执行：
   - **Preflight 检查**：必须在 `userDefinedAnalyses` 页面，且无打开的弹窗
   - **打开导入对话框** → 用原生 setter 把 JSON 粘进 textarea
   - **点确认** → 等待对话框关闭
   - **搜索人群** → 匹配 → 点击「应用人群」
   - **选择阿里妈妈渠道**（radio 自动勾选）
   - **自动应用** 或 **等待手动确认**（最长 30 分钟）
   - **DataHub 状态轮询**（最长 5 分钟，等待"已应用"）

**全程插件锁**：`window.__dmpAutomationRunning` 防止并发执行多个任务。

### 3.8 批量模式（组合模式）

**入口**：数据引擎人群圈包顶部「批量模式」切换 Tab

**作用**：一次应用**一整个文件夹**的方案，所有方案的参数**按参数名聚合**后批量执行。

**典型场景**：
- 你有 10 个连衣裙相关方案（不同版型、不同场景）
- 想统一改"消费频次 ≥ 3 次"这个参数
- 传统做法：挨个打开改 → 太痛苦
- 批量模式：选中文件夹 → 改一次 → 批量应用到 10 个方案

参数聚合规则：**同名参数取并集**，不同名参数各带各的。

## 四、数据引擎取数模板（SolutionCenter）详解

数据引擎取数模板是**方案的"GitHub"**——保存、版本、分享、复用全在这里。

### 4.1 我的方案 / 公共方案

顶部 Tab 切换：
- **我的方案**：你自己保存的方案（含草稿）
- **公共方案**：所有人可见的已发布方案（团队知识沉淀）

**状态过滤**：全部 / 草稿 / 已发布

### 4.2 文件夹与方案管理

左侧是文件夹树（`FolderTree.vue`），支持：
- **新建文件夹**：按业务线/项目/人群包分类
- **拖拽移动方案**：在文件夹之间拖动方案卡片
- **拖拽排序**：文件夹内部拖拽方案改变顺序（后端 `/reorder`）
- **文件夹口令分享**：整个文件夹打包分享（见 4.4）

### 4.3 草稿 → 发布流程

**草稿**：
- 在数据引擎人群圈包点「存草稿」→ 自动进入"我的方案 / 草稿"
- 只有自己可见，随时可改

**发布**：
- 方案卡片点「发布」→ 状态变为"已发布"
- 默认进入"我的方案"，可勾选"同步到公共方案"让全员可见
- 发布后**生成快照**，编辑会创建"编辑草稿"（不影响线上版本）

**编辑已发布方案**：
- 点「生成编辑草稿」→ 复制一份草稿出来改
- 改完再次发布 → 覆盖线上版本

### 4.4 口令分享与导入（Ctrl+V）

**生成口令**（仅"我的方案"的文件夹支持）：
1. 文件夹上右键 / 点「分享」
2. 系统生成一段加密口令字符串（包含文件夹 + 所有方案的完整快照）
3. 复制口令发给同事

**导入口令**：
1. 接收方在数据引擎取数模板**任意位置按 Ctrl+V**
2. 系统自动识别粘贴板里的口令 → 弹出预览对话框
3. 显示文件夹结构、方案数量、包含参数
4. 确认导入 → 整个文件夹 + 方案完整复制到"我的方案"

**注意**：
- 口令分享的是**快照**，与原文件夹解耦（原文件夹后续改动不影响已分享的）
- 自定义字段绑定关系会一起带过去

### 4.5 自定义字段绑定

**作用**：给方案打"业务标签"，便于检索和归档。

**操作**：
1. 方案卡片 → 「自定义字段」
2. 弹出字段编辑对话框
3. 字段定义由管理员在后端 `/api/solutions/custom-fields` 维护

## 五、达摩盘取数（TaskCenter）详解

达摩盘取数是 **DMP 批量提取任务**的进度看板。

### 5.1 DMP 批量任务

**什么是 DMP 批量任务**：一次性向达摩盘提交多个人群包的"画像透视"请求，批量提取覆盖人数、Rebase 后人数等指标。

**入口**：达摩盘取数 → 「新建任务」

**任务类型**：
- 批量提取（最常）：提交一批人群包，等所有透视完成
- 单包重试：对失败的人群包单独重跑

### 5.2 任务卡片状态机

每张任务卡片可能的状态：

| 状态 | 含义 | 用户能做什么 |
|------|------|------------|
| **排队中** | 已提交，等待插件空闲 | 取消 |
| **Phase1 搜索匹配** | 在 DMP 列表页搜人群包 | 取消 |
| **Phase2 等待透视入口** | 等 DMP 出现"画像透视"按钮（最长 30 分钟） | 取消 |
| **Phase3 提取中** | 进入透视页，正在 hook 接口拿数据 | 取消 |
| **完成** | 所有人群包提取成功 | 查看结果、导出 |
| **部分失败** | 部分包失败 | 重试失败项 |
| **失败** | 整个任务失败 | 查看原因、重试 |
| **已取消** | 用户主动取消 | — |

### 5.3 进度查看与取消

- **进度条**：实时显示 `已完成 / 总数`
- **当前阶段**：文字说明正在 Phase1/2/3
- **取消按钮**：任意进行中状态可取消，已开始的子任务会跑完，未开始的丢弃
- **失败原因**：鼠标悬停失败卡片，tooltip 显示详细错误

### 5.4 常见问题排查

| 问题 | 原因 | 解决 |
|------|------|------|
| 卡在 Phase1 不动 | DMP 列表页结构变了 / 网络慢 | 刷新 DMP 页面后重试 |
| Phase2 超时（30 分钟） | 达摩盘审核慢 / 人群包未生效 | 去 DMP 后台手动看包状态 |
| Phase3 提取数据为空 | 透视页接口 hook 失败 | 检查插件是否最新、刷新透视页 |
| 一直显示"排队中" | 另一个任务在跑（插件单例锁） | 等待或取消占用中的任务 |

## 六、达摩盘（DMP）批量提取原理与实操

> 这一章写给"想知道背后在干嘛"的同学，以及需要排查问题的维护人。

### 6.1 三阶段流程

```
┌──────────┐    ┌──────────────────┐    ┌────────────────────┐
│ Phase 1  │ →  │    Phase 2       │ →  │     Phase 3        │
│ 搜索匹配  │    │  等待画像透视入口 │    │ 透视页提取数据     │
└──────────┘    └──────────────────┘    └────────────────────┘
   ~5秒             0~30分钟                 ~10秒
```

#### Phase 1：搜索匹配人群包

**做什么**：在 DMP 人群列表页搜索目标人群包名称，匹配到精确的一行。

**技术细节**：
- 等待列表稳定（4 次连续 500ms 签名比对 + 2 秒静止）
- 全文匹配单元格文本（避免模糊误中）

#### Phase 2：等待"画像透视"入口

**做什么**：DMP 对新建人群包有个"洞察计算"过程，需等"画像透视"按钮可点。

**技术细节**：
- 每 10 秒扫一次页面，最长 30 分钟
- 超时 → 任务标记失败，提示"达摩盘洞察超时"

#### Phase 3：透视页提取数据

**做什么**：进入透视页，hook 掉 `XMLHttpRequest`，偷取**带鉴权的 API 请求 payload**，然后换 tagId 重放，批量提取所有标签数据。

**技术细节**：
- `hook.js` 在 MAIN world 重写 `XMLHttpRequest.prototype.open/send`
- 捕获到一次合法透视请求后，保留 URL/headers/body 模板
- 后续每个标签只换 `tagId`，复用同一套鉴权参数
- 解析 `chartDataFull` 字段 → 计算 **覆盖人数 / Rebase / Rebase 后人数**

> 🔒 **为什么这么干**：DMP 的透视接口带 CSRF token 和签名，外部直接调不通。hook 一次合法请求后"借船出海"是最稳的方案。

### 6.2 前置条件

- 插件已安装并启用
- 达摩盘（dmp.tmall.com）已登录
- 至少有一个已生效的人群包

### 6.3 实操步骤

1. 达摩盘取数 → 「新建任务」
2. 选择要批量提取的人群包（多选）
3. 点「开始」→ 插件自动打开 DMP 标签页
4. 看着任务卡片状态变化（Phase1 → 2 → 3）
5. 全部完成 → 点卡片查看结果 → 导出 Excel

### 6.4 故障与等待时间说明

| 阶段 | 正常耗时 | 超时阈值 | 超时后行为 |
|------|---------|---------|-----------|
| Phase 1 | 5-10 秒 | 30 秒 | 标记该包失败，继续下一个 |
| Phase 2 | 1-15 分钟 | 30 分钟 | 标记该包失败，继续下一个 |
| Phase 3 | 5-15 秒 | 30 秒 | 标记该包失败，继续下一个 |

## 七、Chrome 插件安装与维护

### 7.1 下载插件

- **入口**：数据引擎人群圈包右上角「下载插件」按钮
- **后端路由**：`GET /api/extension/download`
- **后端行为**：把 `EXTENSION_DIR`（默认 `DMP_PluginV2.1-CDP-Merged/`）打成 zip 流式返回
- **前置**：必须登录，且 `manifest.json` 存在

1. 解压下载的 zip 到本地目录（比如 `D:\cdp-extension\`）
2. Chrome 打开 `chrome://extensions/`
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」→ 选刚才的目录
5. 看到插件卡片 → 确认「已启用」

### 7.3 白名单域名

插件只在这些域名注入 content script（由 `manifest.json` 的 `host_permissions` 决定）：

| 域名 | 用途 |
|------|------|
| `duruo377.top` | CDP 系统自身（接收自动化指令） |
| `databank.tmall.com` | DataBank 自动化 |
| `dmp.tmall.com` | 达摩盘批量提取 |

- **大版本变动**：建议清理 `chrome.storage.session`（在扩展页点"Service Worker" → 控制台执行 `chrome.storage.session.clear()`）

### 9.4 后端配置引擎

**核心文件**：`cdp_backend/engine.py`

**关键类**：`ConfigEngine`

**工作流程**：
1. 启动时加载所有 CSV → 内存缓存
2. 接收前端"生成 JSON"请求 → 按人群包分发
3. 用参数表 + 维表把"友好参数"翻译成"DataBank JSON"
4. **特殊规则**：

5. 返回完整 JSON 给前端

**热重载**：管理后台发布配置后，Gunicorn 收到 SIGHUP，worker 轮流重启加载新 CSV，**用户无感知**。

### 10.1 相对传统手工流程的提效对比

| 环节 | 传统手工 | 用 CDP 系统 | 节省时间 |
|------|---------|------------|---------|

| 配置变更 | 改代码 + 重启 | 维表编辑 → 一键发布 | ~30 分钟 → 2 分钟 |

### 10.2 团队最佳实践

**✅ 推荐**：
- **统一文件夹命名规范**：`业务线-项目-人群类型`，如 `女装-双11-高潜新客`
- **重要方案发公共库**：避免人员流动导致知识流失
- **定期清理草稿**：草稿超过 30 天没动的，要么发布要么删
- **发布配置写说明**：哪怕一句话，半年后回查会感谢自己
- **批量任务错峰**：DMP 透视在白天比较慢，凌晨跑大批量更稳

**❌ 避免**：
- 把口令贴到公开渠道（相当于把方案开源）
- 在配置草稿里堆大量修改再一次发布（出错难定位）
- 停用维表行时不通知团队（前端组件库会突然少选项）
- 多人同时点「自动化圈人」（插件单例锁会让后点的排队）

## 十一、常见问题 FAQ

### 11.1 登录与账号

**Q：忘记密码怎么办？**
A：找 super_admin 在「02 系统账号」→ 「管理」→ 「登录安全」→ 重置密码。

**Q：能自己注册账号吗？**
A：不能。必须 super_admin 发邀请链接。

**Q：邀请链接过期了？**
A：让 super_admin 作废旧的，重新发一条。

### 11.2 数据引擎人群圈包

**Q：拖了人群包但参数表单是空的？**
A：检查 `1.参数表.csv` 里该人群包是否有行；检查维表的"适用的包"是否包含该人群包。

**Q：生成的 JSON 是 `{}`？**
A：大概率所有参数都没填，引擎按"isEmpty 触发器"清空了。至少填一个参数。

**Q：撤销/重做不生效？**
A：撤销栈深度有上限（默认 50 步），超过就丢了。

### 11.3 自动化圈人

**Q：点了"自动化圈人"没反应？**
A：依次排查：
1. 插件是否启用（`chrome://extensions/`）
2. 当前页面是否是 `duruo377.top`
3. 是否已登录 DataBank
4. F12 控制台有没有报错（关键字 `CDP_AUTOMATE_DATABANK`）

**Q：卡在"等待手动确认"？**
A：插件默认先尝试自动应用，失败才回退到手动。看到提示时，去 DataBank 页面手动点一下确认即可（30 分钟内）。

**Q：提示"另一个任务正在执行"？**
A：插件单例锁。要么等当前任务跑完，要么去达摩盘取数取消。

### 11.4 数据引擎取数模板

**Q：Ctrl+V 没反应？**
A：粘贴板里必须是有效的口令字符串（通常以特定前缀开头，长度 >100）。重新复制一次。

**Q：公共方案能改吗？**
A：不能直改，点「生成编辑草稿」改自己的副本，发布后可以选择"覆盖公共版本"。

### 11.5 管理后台

**Q：发布了配置但前端没生效？**
A：让用户强刷（Ctrl+F5）。Gunicorn 是热重载，老页面的内存缓存还在。

**Q：删错了维表行能恢复吗？**
A：草稿阶段可以"放弃草稿"；已发布的只能通过「配置修改记录」找到旧值，手动改回去再发一次。

## 十二、运维与应急

### 12.1 服务管理

**后端服务**（systemd）：
```bash
# 查看状态
sudo systemctl status cdp-backend

# 重启
sudo systemctl restart cdp-backend

# 看日志
tail -f /var/log/cdp/backend.stdout.log
tail -f /var/log/cdp/backend.stderr.log
```

**前端**：静态文件，Nginx 直接服务，无独立进程。

**数据库**：SQLite 单文件，路径在 `cdp_backend/database.py` 配置。

### 12.2 备份

**关键数据**：
- SQLite 数据库文件（用户信息、方案、任务、审计）
- 所有 CSV 配置文件
- `config_versions` 表（发布历史）

**建议备份策略**：每日全量备份 SQLite + CSV，保留 30 天。

### 12.3 常见故障

| 故障 | 排查 |
|------|------|
| 全员打不开 | 检查 Nginx → Gunicorn → 服务器磁盘/内存 |
| 个别用户 401 | 该用户 session 失效，让其重新登录 |
| 生成 JSON 报 500 | 看后端 stderr，多半是 CSV 格式错误（多了逗号、少了引号） |
| 插件下载 404 | `EXTENSION_DIR` 路径不对，或 `manifest.json` 缺失 |

## 结语

这份手册覆盖了从**新手 10 分钟跑通**，到**管理员全套操作**，再到**维护人排障**的全部内容。

**给接手维护人的几句话**：
- 配置引擎的核心在 `cdp_backend/engine.py`，改逻辑表结构时先看这里
- 插件的关键在 `DMP_PluginV2.1-CDP-Merged/hook.js` 和 `databank-automation.js`，DMP/DataBank 页面结构变了要改这两处
- 数据库 schema 在 `cdp_backend/database.py`，新增字段记得写迁移
- 定时备份 SQLite + CSV，这是唯一不能丢的东西

祝顺利！有问题翻「常见问题 FAQ」，再不行翻后端日志。
